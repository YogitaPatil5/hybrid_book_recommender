Semantic Search Engine

  1. Data preparation — the raw catalogue is validated, cleaned and de-duplicated.
  2. Genre tagging — a local LLM (via Ollama) assigns one genre from a fixed taxonomy; a keyword classifier is the offline fallback.
  3. Embeddings — each book's title, genre and description are encoded by {{ stats.embedding_model or "all-MiniLM-L6-v2" }} into a normalised vector.
  4. FAISS index — inner-product search over normalised vectors equals cosine similarity; genre filters run inside the index.
  5. Query time — your query is embedded the same way and the closest books are returned, de-duplicated across editions.
{% if stats.knn_available %}

Collaborative Filtering

  1. Data — Book-Crossing: ~1.15M ratings joined with the book catalogue; HTML entities, ISBNs and years cleaned.
  2. Implicit feedback — a rating of 0 means "interacted, no score"; it is never confused with "never read" (mode: {{ stats.knn_mode or "binary" }}).
  3. Filtering — engaged readers and books read by enough of them; editions merged by title + author.
  4. Model — item–item k-NN (cosine) over a sparse book × reader matrix covering {{ "{:,}".format(stats.knn_books) }} books.
  5. Evaluation — Hit-Rate@5 on held-out readers, compared with a popularity baseline (bookmind-pipeline evaluate-knn).
